### `ls`

`ls` показывает содержимое директории.

```
ls
```

Частые варианты:

```
ls -l
```

Показывает подробную информацию:

```
-rw-r--r-- 1 root root  1200 Jul  3 10:20 nginx.conf
drwxr-xr-x 2 root root  4096 Jul  3 10:21 sites-enabled
```

```
ls -la
```

Показывает все файлы, включая скрытые.

Скрытые файлы в Linux начинаются с точки:

```
.bashrc
.ssh
.git
.env
```

```
ls -lh
```

Показывает размеры в удобном формате:

```
1.5K
20M
4.0G
```

```
ls -ltr
```

Сортирует по времени изменения. Удобно смотреть последние изменённые файлы в логах или конфигах.

### `cd`

`cd` меняет текущую директорию.

```
cd /etc/nginx
```

Перейти в домашнюю директорию:

```
cd
```

или:

```
cd ~
```

Перейти на уровень выше:

```
cd ..
```

Перейти в предыдущую директорию:

```
cd -
```

Пример:

```
cd /var/log
cd -
```

## `pwd`

`pwd` показывает текущую директорию.

```
pwd
```

Пример:

```
/home/user
```

Полезно, когда работаешь по SSH и нужно понять, где ты сейчас находишься.

### `cp`

`cp` копирует файлы и директории.

Скопировать файл:

```
cp nginx.conf nginx.conf.bak
```

Скопировать файл в другую директорию:

```
cp app.conf /etc/myapp/
```

Скопировать директорию рекурсивно:

```
cp -r app app-backup
```

Сохранить права, владельца и timestamps:

```
cp -a app app-backup
```

`-a` часто используют для аккуратного бэкапа директорий.

Пример перед изменением конфига:

```
cp /etc/nginx/nginx.conf /etc/nginx/nginx.conf.bak
```

### `mv`

`mv` перемещает или переименовывает файлы.

Переименовать файл:

```
mv old.conf new.conf
```

Переместить файл:

```
mv app.log /var/log/myapp/
```

Переименовать директорию:

```
mv app app-old
```

Важно: в Linux переименование и перемещение внутри одной файловой системы — это обычно быстрая операция, потому что меняется запись в директории, а не копируются данные файла.

### `mkdir`

`mkdir` создаёт директорию.

```
mkdir logs
```

Создать вложенные директории:

```
mkdir -p /opt/myapp/logs
```

Без `-p` команда упадёт, если промежуточных директорий не существует.

```
mkdir /opt/myapp/logs
# ошибка, если /opt/myapp ещё нет
```

Для DevOps часто используется при подготовке директорий под приложение:

```
mkdir -p /var/lib/myapp
mkdir -p /var/log/myapp
mkdir -p /etc/myapp
```

### `touch`

`touch` создаёт пустой файл или обновляет время изменения существующего файла.

Создать файл:

```
touch app.log
```

Обновить timestamp файла:

```
touch nginx.conf
```

Посмотреть timestamp можно через:

```

```

Частые сценарии:

```
touch /tmp/testfile

```

### `rm`

`rm` удаляет файлы.

Удалить файл:

```
rm app.log
```

Удалить директорию рекурсивно:

```
rm -r old-app
```

Удалить без вопросов:

```
rm -f app.log
```

Опасная команда:

```
rm -rf /some/path
```

`-r` — рекурсивно.  
`-f` — force, не спрашивать подтверждения.

Очень опасно:

```
rm -rf /
rm -rf /*
rm -rf $EMPTY_VAR/*
```

Пример проблемы:

```
DIR=""
rm -rf $DIR/*
```

Команда может превратиться в:

```
rm -rf /*
```

### `cat`

`cat` выводит содержимое файла целиком.

```
cat /etc/hosts
```

Подходит для маленьких файлов:

```
cat nginx.conf
cat .env
cat /proc/cpuinfo
```

Неудобен для больших логов, потому что вывалит весь файл в терминал.

Также можно склеивать файлы:

```
cat part1.txt part2.txt > full.txt
```

Перезаписать файл:

```
cat new.conf > app.conf
```

Добавить в конец файла:

```
cat extra.conf >> app.conf
```

### `less`

`less` открывает файл для удобного просмотра.

```
less /var/log/syslog
```

Управление:

```
Space   вниз на страницу
b       вверх на страницу
/word   поиск вперёд
n       следующее совпадение
N       предыдущее совпадение
q       выйти
G       в конец файла
g       в начало файла
```

`less` удобнее, чем `cat`, для больших логов и конфигов.

Открыть лог и перейти в конец:

```
less +G /var/log/syslog
```

### `head`

`head` показывает начало файла.

```
head file.txt
```

По умолчанию показывает первые 10 строк.

Показать первые 50 строк:

### `tail`

`tail` показывает конец файла.

```
tail file.txt
```

По умолчанию показывает последние 10 строк.

Показать последние 100 строк:

```
tail -n 100 /var/log/syslog
```

Очень часто используется для логов:

```
tail -n 50 /var/log/nginx/error.log
```

---
### `tail -f`

`tail -f` показывает конец файла и продолжает следить за новыми строками.

```
tail -f /var/log/nginx/access.log
```

Это один из главных инструментов при debugging.

Например, можно открыть лог и в другом терминале сделать запрос:

```
curl http://localhost
```

А в первом терминале увидеть, что появилось в логе.

Более удобный вариант:

```
tail -F /var/log/myapp/app.log
```

Разница:

```
tail -f
```

следит за конкретным файлом.

```
tail -F
```

лучше переживает log rotation, когда старый лог переименовали, а новый файл создали заново.

Для SRE это важно, потому что логи часто ротируются через `logrotate`.

### `find`

`find` ищет файлы и директории в реальном времени по файловой системе.

Базовый пример:

```
find /etc -name "nginx.conf"
```

Найти все `.log` файлы:

```
find /var/log -name "*.log"
```

Найти только файлы:

```
find /var/log -type f
```

Найти только директории:

```
find /etc -type d
```

Найти файлы больше 100 MB:

```
find /var/log -type f -size +100M
```

Найти файлы, изменённые за последние сутки:

```
find /var/log -type f -mtime -1
```

Найти файлы старше 7 дней:

```
find /tmp -type f -mtime +7
```

Удалить найденные файлы:

```
find /tmp -type f -mtime +7 -delete
```

Более безопасный вариант — сначала посмотреть:

```
find /tmp -type f -mtime +7
```

и только потом удалить.

Выполнить команду для каждого найденного файла:

```
find /var/log -type f -name "*.log" -exec ls -lh {} \;
```

`{}` — место, куда подставляется найденный файл.  
`\;` — конец команды для `-exec`.

### `locate`

`locate` быстро ищет файлы по заранее созданной базе.

```
locate nginx.conf
```

Плюс: работает очень быстро.

Минус: может не видеть новые файлы, если база ещё не обновилась.

Обновить базу:

```
sudo updatedb
```

Разница:

```
find
```

ищет прямо сейчас по файловой системе.

```
locate
```

ищет по индексу.

На серверах `locate` может быть не установлен по умолчанию.

### `stat`

`stat` показывает подробную информацию о файле.

```
stat file.txt
```

Пример вывода:

```
File: file.txt
Size: 1200
Blocks: 8
IO Block: 4096 regular file
Device: 802h/2050d
Inode: 1234567
Links: 1
Access: 2026-07-03 10:00:00
Modify: 2026-07-03 10:01:00
Change: 2026-07-03 10:02:00
Birth: -
```

Важные поля:

```
Size    размер файла
Inode   номер inode
Links   количество hard links
Access  время последнего чтения
Modify  время изменения содержимого
Change  время изменения метаданных
Birth   время создания, если поддерживается файловой системой
```

Важно различать:

```
mtime — изменилось содержимое файла
ctime — изменились метаданные файла: права, владелец, links и т.д.
atime — файл был прочитан
```

### `file`

`file` определяет тип файла по содержимому, а не только по расширению.

```
file nginx.conf
```

Примеры:

```
file /bin/bash
# ELF 64-bit executable

file archive.tar.gz
# gzip compressed data

file image.png
# PNG image data

file script.sh
# Bourne-Again shell script text executable
```

В Linux расширение файла не является главным источником истины.

Файл может называться `app.txt`, но быть бинарником:

```
file app.txt
```

### Hard links

Hard link — это ещё одно имя для того же самого inode.

Создать hard link:

```
ln file.txt hardlink.txt
```

Проверить inode:

```
ls -li
```

Пример:

```
1234567 -rw-r--r-- 2 user user 100 Jul  3 10:00 file.txt
1234567 -rw-r--r-- 2 user user 100 Jul  3 10:00 hardlink.txt
```

Оба файла имеют одинаковый inode.

Число `2` после прав доступа означает количество hard links:

```
-rw-r--r-- 2 user user
```

Это значит, что на один inode указывают два имени.

Если изменить один файл:

```
echo "hello" >> file.txt
```

изменения будут видны и через `hardlink.txt`, потому что это один и тот же файл на уровне inode.

Если удалить один hard link:

```
rm file.txt
```

данные не исчезнут, потому что второй hard link ещё указывает на inode:

```
cat hardlink.txt
```

Файл реально удалится только когда:

```
количество hard links = 0
и файл больше не открыт процессами
```

Ограничения hard link:

```
нельзя создать hard link на директорию обычным способом
нельзя создать hard link между разными файловыми системами
```

Почему нельзя между разными файловыми системами?

Потому что inode существует внутри конкретной файловой системы.  
Например, inode на `/dev/sda1` не имеет смысла на `/dev/sdb1`.

### Symbolic links

Symbolic link, symlink или soft link — это отдельный файл, который хранит путь к другому файлу.

Создать symlink:

```
ln -s /etc/nginx/nginx.conf nginx-link.conf
```

Посмотреть:

```
ls -l
```

Пример:

```
nginx-link.conf -> /etc/nginx/nginx.conf
```

Symlink имеет свой собственный inode.

Проверить:

```
ls -li
```

Symlink можно делать:

```
на файлы
на директории
между разными файловыми системами
на несуществующий путь
```

Пример symlink на директорию:

```
ln -s /var/log/nginx nginx-logs
cd nginx-logs
```

Если удалить оригинальный файл:

```
rm /etc/nginx/nginx.conf
```

symlink останется, но станет битым:

```
nginx-link.conf -> /etc/nginx/nginx.conf
```

При попытке открыть будет ошибка:

```
No such file or directory
```

---
## Разница hard link и symlink

|Параметр|Hard link|Symlink|
|---|---|---|
|Что это|Ещё одно имя того же inode|Отдельный файл со ссылкой на путь|
|Inode|Такой же, как у оригинала|Свой собственный inode|
|Работает без оригинального имени|Да|Нет|
|Можно ссылаться на директории|Обычно нет|Да|
|Можно между файловыми системами|Нет|Да|
|Может быть битым|Нет|Да|
|Создание|`ln file hardlink`|`ln -s file symlink`|

### Inode

`inode` — это структура данных файловой системы, которая хранит метаданные файла.

Inode хранит:

```
права доступа
владельца
группу
размер
timestamps
ссылки на блоки данных на диске
количество hard links
```

Важно: имя файла не хранится внутри inode.

Имя файла хранится в директории.

Директория по сути содержит соответствие:

```
filename -> inode number
```

Пример:

```
ls -li
```

Вывод:

```
1234567 -rw-r--r-- 1 user user 100 Jul  3 10:00 file.txt
```

`1234567` — это inode number.

Файл на уровне файловой системы — это не совсем “имя файла”.  
Файл — это inode + данные.  
Имя — это ссылка из директории на inode.

---

Linux удаление файла через `rm` не обязательно сразу освобождает место на диске.

Когда ты делаешь:

```
rm app.log
```

Linux удаляет имя файла из директории.

Но если файл открыт процессом, данные остаются на диске, пока процесс не закроет file descriptor.

То есть файл исчезает из `ls`, но место на диске не освобождается.

Посмотреть такие файлы можно через:

```
lsof | grep deleted
```

Для SRE это частый кейс:

```
df -h показывает, что диск забит
du -sh /var/log/* не показывает больших файлов
причина может быть в удалённом, но открытом файле
```

Проверка:

```
lsof +L1
```

`+L1` показывает файлы, у которых link count меньше 1, то есть удалённые, но всё ещё открытые.
