### Пользователи и группы

Linux — многопользовательская операционная система.

Каждый процесс всегда запускается **от имени какого-либо пользователя (user)**.

Каждый пользователь принадлежит одной или нескольким группам.

Это позволяет:

- разграничивать доступ
- изолировать сервисы
- управлять безопасностью

Например:

```
root
nginx
mysql
postgres
jenkins
ubuntu
```

Очень часто сервис запускается не от root, а от отдельного пользователя.

Например:

```
nginx -> user nginx
postgres -> user postgres
mysql -> user mysql
```

Это уменьшает последствия взлома.

Если злоумышленник получит доступ к nginx-процессу, он получит права пользователя nginx, а не root.

### UID и GID

На самом деле ядро работает **не с именами**, а с числами.

Каждый пользователь имеет:

```
UID (User ID)
```

Каждая группа имеет:

```
GID (Group ID)
```

Пример:

```
rootUID = 0
GID = 0
```

Обычные пользователи обычно:

```
UID = 1000+
```

Системные пользователи:

```
1...
100...
999...
```

Посмотреть свой UID:

```
id
```

или

```
id username
```

Пример:

```
uid=1000(user)
gid=1000(user)
groups=1000(user),27(sudo)
```

### `/etc/passwd`

Файл содержит список пользователей.

Посмотреть:

```
cat /etc/passwd
```

Пример строки:

```
user:x:1000:1000:User:/home/user:/bin/bash
```

Поля:

```
login
password placeholder
UID
GID
comment
home directory
shell
```

Паролей здесь нет.

Вместо них:

```
x
```

---
### `/etc/shadow`

Здесь находятся хэши паролей.

Посмотреть может только root.

Пример:

```
root:$6$.......
```

Здесь также хранится:

- дата смены пароля
- срок действия
- блокировка аккаунта

Права:

```
-r-------- root root
```

---

### `/etc/group`

Файл содержит группы.

Пример:

```
sudo:x:27:user
docker:x:999:user
```

Формат:

```
group
password placeholder
GID
members
```

### Права rwx

Каждый объект имеет три набора прав:

```
owner
group
others
```

Каждый набор содержит:

```
rwx
```

где

```
r = read = 4
w = write = 2
x = execute = 1
```

Например:

```
-rwxr-x---
```

Разбиваем:

```
rwxr-x---
```

Получаем:

```
owner  -> rwx
group  -> r-x
others -> ---
```

---
### Права на файл

Для файла:

```
r
```

можно читать содержимое.

```
cat
less
vim
```

---

```
w
```

можно изменять содержимое.

---

```
x
```

можно запускать файл как программу.

Без x:

```
./script.sh
Permission denied
```

---

### Права на директорию

Для директории права работают иначе.

### r

Можно посмотреть список файлов.

```
ls
```

---

### w

Можно:

- создавать
- удалять
- переименовывать

файлы внутри директории.

---

### x

Самое важное право.

Позволяет:

- входить в каталог

```
cd
```

- обращаться к файлам по имени

Без x даже наличие r не поможет.

Например:

```
dr--r--r--
```

```
ls
```

может показать список файлов,

но

```
cd
```

не получится.

### chmod

Изменяет права.

Символьный вариант:

```
chmod u+x file
chmod g-w file
chmod o-r file
```

или

```
chmod a+r file
```

---

Числовой вариант:

```
chmod 755 file
chmod 644 file
```

---

### chown

Меняет владельца.

```
chown user file
```

или

```
chown user:group file
```

Рекурсивно:

```
chown -R user:group directory
```

---

### chgrp

Меняет только группу.

```
chgrp developers file
```

---

### Octal permissions

Каждое право — бит.

```
r = 4
w = 2
x = 1
```

Получаем:

```
7 = rwx
6 = rw-
5 = r-x
4 = r--
3 = -wx
2 = -w-
1 = --x
0 = ---
```

Самые популярные:

#### 644

```
rw-r--r--
```

Обычный файл.

---

#### 755

```
rwxr-xr-x
```

Исполняемый файл.

---

#### 600

```
rw-------
```

Закрытый файл.

Например:

```
~/.ssh/id_ed25519
```

---

#### 700

```
rwx------
```

Только владелец.

### umask

`umask` задаёт **маску**, которая определяет, какие права **не будут выданы** новым файлам и каталогам по умолчанию.

Важно: это не права сами по себе, а набор битов, которые нужно убрать.

Базовые права при создании:

- файл — `666` (`rw-rw-rw-`)
- директория — `777` (`rwxrwxrwx`)

Например:

```
umask 022
```

Тогда:

```
Файл:666 - 022 = 644
Директория:777 - 022 = 755
```

Ещё пример:

```
umask 077
```

Получим:

```
Файл:600
Директория:700
```

Посмотреть текущую маску:

```
umask
```

---

### SUID

Special User ID.

```
-rwsr-xr-x
```

или

```
4755
```

При запуске файла процесс получает UID владельца файла.

Самый известный пример:

```
/usr/bin/passwd
```

Обычный пользователь меняет пароль, хотя файл `/etc/shadow` доступен только root. Это возможно потому, что `passwd` запускается с эффективным UID владельца (root).

Посмотреть:

```
find / -perm -4000
```

---

### SGID

```
2755
```

Для файла:

процесс получает GID владельца файла.

Для директории:

все новые файлы наследуют группу директории.

Очень полезно для общих каталогов.

Например:

```
/shared
```

Все новые файлы автоматически будут принадлежать группе:

```
developers
```

# Sticky bit

```
1777
```

Пример:

```
/tmp
```

Любой пользователь может создать файл.

Но удалить может только:

- владелец файла
- владелец директории
- root

Без Sticky Bit любой пользователь с правом записи в каталог мог бы удалять чужие файлы.

# ACL

Обычные права позволяют назначить доступ только:

- владельцу
- группе
- остальным

ACL (**Access Control List**) позволяют выдавать права конкретным пользователям и группам без смены владельца или основной группы.

Например:

```
owner -> alice
group -> developers
дополнительно:bob -> rw
charlie -> r
qa -> rx
```

---

# getfacl

Показать ACL.

```
getfacl file.txt
```

Пример вывода:

```
user::rw-
user:bob:r--
group::r--
mask::r--
other::---
```

---

# setfacl

Добавить права:

```
setfacl -m u:bob:rw file.txt
```

Удалить:

```
setfacl -x u:bob file.txt
```

Удалить все ACL:

```
setfacl -b file.txt
```

# sudo

`sudo` позволяет выполнить команду с правами другого пользователя (по умолчанию — `root`).

Пример:

```
sudo systemctl restart nginx
```

После успешной аутентификации `sudo` временно повышает привилегии только для этой команды.

Это безопаснее, чем постоянная работа под `root`.

---

# `/etc/sudoers`

Главный файл конфигурации `sudo`.

Пример правила:

```
user ALL=(ALL) ALL
```

Означает:

- пользователь `user`
- на любых хостах (`ALL`)
- может выполнять команды от имени любых пользователей (`(ALL)`)
- любые команды (`ALL`)

Также часто используются группы:

```
%sudo ALL=(ALL:ALL) ALL
```

или

```
%wheel ALL=(ALL) ALL
```

# visudo

Редактировать `/etc/sudoers` следует только через:

```
visudo
```

Почему:

- проверяет синтаксис перед сохранением
- предотвращает повреждение файла
- блокирует одновременное редактирование

Если случайно испортить `/etc/sudoers`, можно потерять возможность использовать `sudo`.

---

# Почему нельзя всем давать `sudo ALL=(ALL) NOPASSWD:ALL`

Правило:

```
user ALL=(ALL) NOPASSWD:ALL
```

означает:

- пользователь может выполнять **любую** команду от имени **любого** пользователя;
- пароль при этом **не запрашивается**.

Фактически это эквивалентно выдаче полного доступа `root`.

Основные риски:

- любая уязвимость в учётной записи пользователя сразу приводит к полному захвату системы;
- вредоносные скрипты могут незаметно выполнять команды с максимальными привилегиями;
- исчезает дополнительная защита в виде запроса пароля перед опасными действиями;
- нарушается принцип **минимально необходимых привилегий (Principle of Least Privilege)**.

В production-системах рекомендуется выдавать только те команды, которые действительно необходимы, например:

```
deploy ALL=(root) NOPASSWD: /bin/systemctl restart nginx
```

Так пользователь сможет перезапускать только `nginx`, но не получит полный доступ к системе.
