# Что такое процесс

**Процесс (process)** — это экземпляр запущенной программы.

Когда вы запускаете программу:

```
nginx
```

ядро Linux:

- выделяет память;
- создает PID;
- открывает необходимые файлы;
- создает таблицу дескрипторов;
- назначает процесс планировщику CPU.

После этого программа становится процессом.

Пример:

```
Файл на диске:

/usr/bin/bash

        │

запуск

        ▼

Процесс:

PID=3521
bash
```

Одна программа может иметь множество процессов.

Например:

```
python app.py
python app.py
python app.py
```

Это три независимых процесса.

---

## Что содержит процесс

У процесса есть множество атрибутов.

Например:

- PID
- PPID
- пользователь
- группа
- состояние
- память
- открытые файлы
- сетевые сокеты
- переменные окружения
- приоритет
- текущая рабочая директория

---

## Где это хранится

Практически всё можно посмотреть через `/proc`.

Например:

```
/proc/1234/
```

Там находятся

```
cmdline
status
maps
fd/
environ
stat
cwd
exe
```

Это виртуальная файловая система, создаваемая ядром.

---

## Как создаются процессы

Практически всегда схема такая:

```
fork()
      ↓
создается копия процесса
      ↓
exec()
      ↓
загружается новая программа
```

Именно поэтому у каждого процесса есть родитель.

---

# PID

**PID (Process ID)** — уникальный идентификатор процесса.

Например

```
PID 1
systemd

PID 234
sshd

PID 4120
bash

PID 5601
nginx
```

Посмотреть PID:

```
echo $$
```

или

```
ps
```

---

## Почему PID нужен

Практически все команды работают через PID.

Например

```
kill 3245
```

или

```
strace -p 3245
```

или

```
gdb -p 3245
```

---

# PPID

PPID — Parent Process ID.

То есть PID родительского процесса.

Посмотреть:

```
ps -ef
```

или

```
ps -o pid,ppid,cmd
```

Например

```
PID   PPID   CMD

1       0    systemd

345     1    sshd

500    345   bash

820    500   vim
```

Получается дерево:

```
systemd
    │
    └── sshd
            │
            └── bash
                    │
                    └── vim
```

---

# ps

Главная команда просмотра процессов.

Самая популярная:

```
ps aux
```

или

```
ps -ef
```

---

## Что означает ps aux

```
USER
PID
%CPU
%MEM
VSZ
RSS
TTY
STAT
START
TIME
COMMAND
```

Например

```
USER PID %CPU %MEM COMMAND

root 1 0.0 0.3 systemd
```

---

## Полезные варианты

Все процессы:

```
ps -ef
```

Дерево процессов:

```
ps -ef --forest
```

Только нужные поля:

```
ps -o pid,ppid,user,%cpu,%mem,cmd
```

---

# top

Интерактивный просмотр процессов.

Запуск:

```
top
```

Показывает:

- CPU
- RAM
- swap
- load average
- процессы

Можно сортировать:

```
P
```

по CPU.

```
M
```

по памяти.

---

# htop

Более удобная версия top.

Запуск:

```
htop
```

Позволяет:

- искать процессы
- фильтровать
- убивать процессы
- менять nice
- смотреть дерево процессов

На большинстве серверов нужно установить:

```
sudo apt install htop
```

---

# pgrep

Ищет процессы по имени.

Например

```
pgrep nginx
```

```
1123
1124
1125
```

Можно сразу увидеть команду:

```
pgrep -a nginx
```

```
1123 nginx: master
1124 nginx: worker
```

Очень часто используют в скриптах.

---

# pidof

Возвращает PID процесса.

Например

```
pidof nginx
```

```
1123 1124 1125
```

Работает проще, чем pgrep.

---

# kill

Несмотря на название, **kill не обязательно "убивает" процесс**.

Команда **отправляет процессу сигнал**.

Например

```
kill 1234
```

по умолчанию отправляет

```
SIGTERM
```

---

# Signals

Signal — специальное сообщение от ядра или другого процесса.

Примеры:

```
SIGTERM
SIGKILL
SIGSTOP
SIGCONT
SIGHUP
SIGINT
```

Каждый сигнал имеет номер.

Посмотреть:

```
kill -l
```

---

# SIGTERM

Номер:

```
15
```

Это **вежливая просьба завершиться**.

Процесс может:

- сохранить данные;
- закрыть файлы;
- завершить соединения;
- освободить память.

Именно этот сигнал используют почти всегда.

```
kill PID
```

или

```
kill -15 PID
```

---

# SIGKILL

Номер

```
9
```

Ядро моментально уничтожает процесс.

Процесс не может:

- отказаться;
- сохранить данные;
- выполнить cleanup.

Поэтому:

```
kill -9
```

используют только если обычный SIGTERM не помог.

---

# SIGHUP

Исторически означал потерю терминала (_hang up_), а сегодня часто используется как сигнал **перечитать конфигурацию без полной остановки процесса**.

Например:

```
kill -HUP <PID>
```

Многие демоны (например, веб-серверы) после этого перечитывают конфигурацию или переоткрывают лог-файлы.

Важно понимать, что реакция на `SIGHUP` зависит от программы — это соглашение, а не обязательное поведение ядра.

---

# Zombie processes

Zombie — уже завершившийся процесс.

Он:

- не выполняется;
- память освобождена;
- PID еще существует.

Почему?

Потому что родитель еще не забрал код завершения.

В ps:

```
STAT Z
```

---

## Почему появляются

Родитель обязан вызвать

```
wait()
```

Если не вызвал —

получаем zombie.

---

# Orphan processes

Orphan — процесс без родителя.

Например

```
bash
   │
   └── python
```

Закрыли bash.

Python остался работать.

Теперь его родителем становится

```
systemd
```

(PID 1).

Это абсолютно нормальная ситуация.

---

# Foreground/background jobs

Foreground — процесс занимает терминал.

Например

```
vim
```

Пока работает —

терминал занят.

---

Background

```
sleep 100 &
```

Процесс работает в фоне.

Терминал свободен.

---

# jobs

Показать фоновые задачи текущей оболочки:

```
jobs
```

Например

```
[1] Running sleep 100 &
```

---

# fg

Вернуть задачу на передний план:

```
fg %1
```

---

# bg

Продолжить остановленную задачу в фоне:

```
bg %1
```

Часто используют после:

```
Ctrl+Z
```

---

# nohup

По умолчанию процессы, запущенные из терминала, получают `SIGHUP` при закрытии терминала и обычно завершаются.

`nohup` ("no hang up") запускает программу так, чтобы она **игнорировала `SIGHUP`** и продолжила работать после выхода из SSH-сессии.

Например:

```
nohup python app.py &
```

По умолчанию вывод записывается в файл:

```
nohup.out
```

---

# disown

Убирает уже запущенную задачу из списка jobs текущей оболочки.

Например:

```
python app.py &
jobs
disown %1
```

После этого оболочка перестает отслеживать задачу, и при закрытии терминала она не будет автоматически завершена оболочкой (если программа не зависит от терминала).

---

# nice

Каждый процесс имеет значение **nice**.

Диапазон:

```
-20 ... 19
```

- **-20** — максимальный приоритет.
- **19** — минимальный приоритет.

По умолчанию:

```
0
```

Запустить процесс с низким приоритетом:

```
nice -n 10 backup.sh
```

---

# renice

Изменить приоритет уже работающего процесса:

```
renice 5 -p 1234
```

Для повышения приоритета (уменьшения nice, например до отрицательных значений) обычно требуются права суперпользователя.

---

# Как найти процесс, который грузит CPU

Самый простой способ:

```
top
```

или

```
htop
```

Из командной строки:

```
ps -eo pid,user,%cpu,cmd --sort=-%cpu | head
```

Покажет процессы, отсортированные по использованию CPU.

---

# Как найти процесс, который ест память

В `top` нажмите:

```
M
```

Или выполните:

```
ps -eo pid,user,%mem,rss,cmd --sort=-%mem | head
```

`RSS` показывает объем физической памяти (RAM), используемой процессом.

---

# Как найти процесс, который держит файл

Используется команда:

```
lsof /path/to/file
```

Пример:

```
lsof /var/log/app.log
```

Можно также найти процессы, открывшие файлы в каталоге:

```
lsof +D /var/log
```

Это одна из самых частых команд при поиске причин, почему файл нельзя удалить или файловая система не размонтируется.

---

# Как найти процесс, который слушает порт

Современный способ — `ss`:

```
ss -ltnp
```

Например:

```
ss -ltnp | grep :80
```

Покажет процесс, который слушает TCP-порт 80.

Также можно использовать:

```
lsof -i :80
```

или (на старых системах):

```
netstat -tulpn
```

хотя `netstat` сегодня считается устаревшим и чаще заменяется командой `ss`.
