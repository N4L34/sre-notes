# Пользователи Linux

Каждый процесс в Linux выполняется **от имени какого-либо пользователя (UID)**.

Именно пользователь определяет:

- права на файлы;
- какие процессы можно завершать;
- какие сетевые порты можно открывать;
- какие команды можно выполнять через sudo;
- доступ к устройствам.

Информация о пользователях хранится в:

```
/etc/passwd
/etc/shadow
/etc/group
```

---

# `useradd`

Создает нового пользователя.

Пример:

```
sudo useradd alice
```

После создания пользователь обычно ещё:

- не имеет пароля;
- домашняя директория может не создаться (зависит от параметров).

Создать пользователя вместе с домашней директорией:

```
sudo useradd -m alice
```

Задать shell:

```
sudo useradd -m -s /bin/bash alice
```

Указать UID:

```
sudo useradd -u 1500 alice
```

Добавить сразу в группу:

```
sudo useradd -G docker,sudo alice
```

---

Посмотреть информацию:

```
id alice
```

Например:

```
uid=1001(alice)gid=1001(alice)groups=1001(alice),27(sudo),998(docker)
```

---

# `usermod`

Изменяет существующего пользователя.

Добавить в дополнительную группу:

```
sudo usermod -aG docker alice
```

Очень важно использовать:

```
-aG
```

а не просто

```
-G
```

Иначе список дополнительных групп будет полностью заменён.

---

Изменить shell:

```
sudo usermod -s /bin/zsh alice
```

Переименовать пользователя:

```
sudo usermod -l newname oldname
```

Изменить домашнюю директорию:

```
sudo usermod -d /home/newhome alice
```

Переместить домашнюю директорию:

```
sudo usermod -d /home/newhome -m alice
```

---

# `userdel`

Удаляет пользователя.

Удалить только запись:

```
sudo userdel alice
```

Домашняя директория останется.

Удалить вместе с домашней директорией:

```
sudo userdel -r alice
```

---

# `groupadd`

Создает новую группу.

```
sudo groupadd developers
```

Проверить:

```
grep developers /etc/group
```

Добавить пользователя:

```
sudo usermod -aG developers alice
```

---

# `passwd`

Устанавливает пароль пользователя.

Для себя:

```
passwd
```

Для другого пользователя:

```
sudo passwd alice
```

Заблокировать пароль:

```
sudo passwd -l alice
```

Разблокировать:

```
sudo passwd -u alice
```

# SSH keys

SSH-аутентификация основана на криптографии с открытым ключом.

Есть два ключа:

```
private keypublic key
```

Пример:

```
~/.ssh/id_ed25519~/.ssh/id_ed25519.pub
```

Private key хранится только у владельца.

Public key копируется на сервер.

---

Создать ключ:

```
ssh-keygen -t ed25519
```

Получится:

```
id_ed25519id_ed25519.pub
```

---

Подключение выглядит так:

```
Client
   │
   │ private key
   ▼
SSH
   ▲
   │
Server
authorized_keys
```

Если сервер смог проверить подпись клиента —

доступ разрешается.

Сам приватный ключ никогда не передается по сети.

---

# `~/.ssh/authorized_keys`

Это список публичных ключей, которым разрешён вход.

Например:

```
~/.ssh/authorized_keys
```

Содержимое:

```
ssh-ed25519 AAAAC3Nza...
```

Каждая строка —

один разрешенный ключ.

---

Добавить ключ:

```
cat id_ed25519.pub >> ~/.ssh/authorized_keys
```

Или:

```
ssh-copy-id user@server
```

---

Права должны быть правильными:

```
~/.ssh            700
authorized_keys   600
```

Иначе OpenSSH может отказаться использовать файл.

---

# `~/.ssh/config`

Конфигурация SSH-клиента.

Пример:

```
Host prod
    HostName 10.0.0.15
    User deploy
    IdentityFile ~/.ssh/prod_key
```

После этого:

```
ssh prod
```

вместо

```
ssh deploy@10.0.0.15 -i ~/.ssh/prod_key
```

---

Можно хранить:

- пользователя;
- порт;
- ключ;
- ProxyJump;
- ForwardAgent;
- KeepAlive;
- множество других настроек.

---

# `sshd_config`

Главный конфиг SSH-сервера.

Обычно:

```
/etc/ssh/sshd_config
```

После изменения:

```
sudo systemctl restart sshd
```

или

```
sudo systemctl restart ssh
```

(зависит от дистрибутива).

# Password authentication vs Key authentication

### Password authentication

Клиент отправляет логин.

Сервер просит пароль.

Пароль проверяется по:

```
/etc/shadow
```

Недостатки:

- можно подобрать;
- возможен brute force;
- пароль могут украсть.

---

### Key authentication

Клиент подписывает случайное сообщение своим приватным ключом.

Сервер проверяет подпись публичным ключом.

Преимущества:

- пароль вообще не передается;
- практически невозможно подобрать;
- значительно безопаснее.

Именно этот способ считается стандартом для продакшн-серверов.

---

# Root login через SSH

Разрешает или запрещает вход пользователем root.

```
PermitRootLogin yes
```

или

```
PermitRootLogin no
```

Обычно рекомендуется:

```
PermitRootLogin no
```

Почему:

- невозможно подобрать пароль root по SSH;
- весь доступ идет через обычного пользователя;
- все действия фиксируются через sudo.

---

# Как безопасно дать доступ на сервер

Правильная схема:

Создать пользователя.

```
useradd -m alice
```

Добавить публичный ключ:

```
~alice/.ssh/authorized_keys
```

При необходимости:

```
usermod -aG sudo alice
```

или

```
usermod -aG docker alice
```

Запретить пароль:

```
PasswordAuthentication no
```

Запретить root:

```
PermitRootLogin no
```

Так работает большинство production-серверов.

---

# Как забрать доступ

Самый быстрый способ —

удалить ключ из:

```
authorized_keys
```

Либо полностью удалить пользователя:

```
sudo userdel -r alice
```

Либо заблокировать аккаунт:

```
sudo passwd -l alice
```

Можно также удалить пользователя из привилегированных групп (`sudo`, `docker` и т. п.), если нужно лишь ограничить права, а не полностью лишить доступа.

# `who`

Показывает, кто сейчас вошёл.

Пример:

```
who
```

```
alice pts/0 2026-07-04 10:00bob   pts/1 2026-07-04 11:15
```

---

# `w`

Более подробная информация.

Показывает:

- пользователей;
- время входа;
- источник подключения;
- текущую команду;
- загрузку системы.

Например:

```
w
```

```
USER     TTY      FROM        LOGIN@   IDLE   JCPU   PCPU WHATalice    pts/0    10.0.0.5    10:00    5:00   0.20s  0.01s vim
```

Для DevOps команда `w` обычно полезнее, чем `who`.

---

# `last`

Показывает историю входов.

Источник данных:

```
/var/log/wtmp
```

Пример:

```
last
```

Вывод:

```
alice pts/0 10.0.0.5 Sat Jul 4 10:00 - 10:30bob   pts/1 10.0.0.8 Fri Jul 3 15:00 - 18:00
```

Полезные варианты:

```
last alice
```

История входов конкретного пользователя.

```
last -10
```

Последние 10 входов.

```
last reboot
```

История перезагрузок сервера.
