# Переменные окружения

Переменные окружения (environment variables) — это пары `имя=значение`, которые shell передает запускаемым процессам.

Например:

```
USER=alice
HOME=/home/alice
PATH=/usr/bin:/bin
```

Их используют практически все программы.

Посмотреть все:

```
env
```

или

```
printenv
```

Посмотреть одну:

```
echo "$HOME"
```

---

## Локальная переменная

```
name=Alice
```

Она существует только внутри текущего shell.

Проверить:

```
echo "$name"
```

---

## export

`export` делает переменную доступной дочерним процессам.

Без export:

```
name=Alice
bash
echo "$name"
```

Получим пусто.

С export:

```
export name=Alice
bash
echo "$name"
```

Получим

```
Alice
```

---

Почему?

Потому что каждый процесс получает копию environment своего родителя.

```
bash
 ├── ls
 ├── python
 └── nginx
```

Все дочерние процессы получают только экспортированные переменные.

---

# PATH

Одна из важнейших переменных.

```
echo "$PATH"
```

Например

```
/usr/local/bin:/usr/bin:/bin:/usr/sbin
```

Shell ищет команды именно здесь.

Когда вводим

```
ls
```

bash делает примерно следующее:

```
ищем ls в/usr/local/bin/usr/bin/bin/usr/sbin
```

и запускает первый найденный.

Проверить:

```
which ls
```

или

```
command -v ls
```

Добавить путь:

```
export PATH=$PATH:/opt/myapp/bin
```

# stdin, stdout, stderr

Каждый процесс получает три файловых дескриптора.

```
0 stdin
1 stdout
2 stderr
```

---

stdin

Вход процесса.

Например

```
cat
```

Все введённое попадёт в stdin.

---

stdout

Обычный вывод.

```
echo hello
```

печатает в stdout.

---

stderr

Вывод ошибок.

Например

```
ls file_not_exists
```

Сообщение об ошибке идет в stderr.

---

# Redirect

## >

Перезаписать файл.

```
echo hello > file.txt
```

Получим

```
hello
```

---

## >>

Добавить в конец.

```
echo world >> file.txt
```

Теперь

```
helloworld
```

---

## <

Подать файл как stdin.

```
sort < numbers.txt
```

То же самое что

```
cat numbers.txt | sort
```

но быстрее.

---

## stderr redirect

```
2>
```

Например

```
ls nofile 2> error.log
```

---

И stdout

```
1>
```

или просто

```
>
```

---

Объединить оба:

```
command > all.log 2>&1
```

# Pipe

```
|
```

Передает stdout одной программы в stdin другой.

```
cat file | grep error
```

Схема

```
stdout
   │
   ▼
stdin
```

# set -u

Ошибка при использовании несуществующей переменной.

```

```

```

```

---

# set -o pipefail

По умолчанию:

```
false | true
```

вернет

```
0
```

что может скрыть ошибку.

С

```
set -o pipefail
```

пайп завершится ошибкой, если любая команда внутри завершилась с ненулевым кодом.

Практически всегда используют вместе:

```
set -euo pipefail
```

Это считается хорошим стилем написания Bash-скриптов.

# Cron-friendly scripts

Скрипт для cron должен:

- использовать абсолютные пути;
- не рассчитывать на интерактивный shell;
- явно задавать нужные переменные окружения;
- писать логи;
- корректно завершаться с кодом `0` при успехе и ненулевым кодом при ошибке.

Пример:

```
#!/usr/bin/env bash
set -euo pipefail

/usr/bin/rsync -a /data /backup
```

# Idempotent scripts

Идемпотентный скрипт можно запускать сколько угодно раз — итоговое состояние системы будет одинаковым.

Плохой пример:

```
mkdir /opt/app
```

При повторном запуске завершится ошибкой.

Хороший пример:

```
mkdir -p /opt/app
```

Другие примеры идемпотентных операций:

- `ln -sfn source target` — безопасно обновляет символическую ссылку;
- `cp -f file dest` — принудительно заменяет файл;
- `install -d /path` — создаёт каталог только при необходимости;
- проверка перед изменением конфигурации (`grep -q ... || echo ... >> file`);
- использование инструментов управления конфигурацией (например, Ansible), которые по своей природе стремятся к идемпотентности.
