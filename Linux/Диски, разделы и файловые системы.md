## Общая картина

В Linux диск обычно проходит такой путь:

```
Физический диск
    ↓
Block device
    ↓
Partition
    ↓
Filesystem
    ↓
Mount point
```

Пример:

```
/dev/sda
  └── /dev/sda1
        └── ext4
              └── mounted to /
```

То есть:

- `/dev/sda` — сам диск;
- `/dev/sda1` — раздел на диске;
- `ext4` — файловая система внутри раздела;
- `/` — точка монтирования.

---

# Block devices

**Block device** — это устройство, с которым Linux работает блоками данных.

Примеры block devices:

```
/dev/sda
/dev/sdb
/dev/nvme0n1
/dev/vda
```

Это могут быть:

- HDD;
- SSD;
- NVMe-диск;
- виртуальный диск в облаке;
- LVM volume;
- RAID device;
- loop device.

Посмотреть block devices:

```
lsblk
```

Пример:

```
NAME        SIZE TYPE MOUNTPOINT
sda          50G disk
├─sda1        1G part /boot
└─sda2       49G part /
```

---

# `/dev/sda`

`/dev/sda` — классическое имя первого SATA/SCSI/виртуального диска.

Примеры:

```
/dev/sda   первый диск
/dev/sdb   второй диск
/dev/sdc   третий диск
```

Разделы называются так:

```
/dev/sda1
/dev/sda2
/dev/sda3
```

Где:

- `/dev/sda` — весь диск;
- `/dev/sda1` — первый раздел;
- `/dev/sda2` — второй раздел.

---

# `/dev/nvme0n1`

`/dev/nvme0n1` — имя NVMe-диска.

Пример:

```
/dev/nvme0n1
```

Расшифровка:

```
nvme0  — первый NVMe controller
n1     — первое namespace-устройство
```

Разделы называются так:

```
/dev/nvme0n1p1
/dev/nvme0n1p2
```

Обрати внимание: у NVMe между именем диска и номером раздела добавляется `p`.

```
/dev/sda1        обычный диск
/dev/nvme0n1p1   NVMe-диск
```

---

# Partitions

**Partition** — это раздел диска.

Один диск можно разделить на несколько частей.

Пример:

```
/dev/sda
├── /dev/sda1    /boot
├── /dev/sda2    /
└── /dev/sda3    swap
```

Зачем нужны разделы:

- отделить `/boot`;
- отделить `/home`;
- сделать swap-раздел;
- использовать разные файловые системы;
- удобнее управлять дисковым пространством;
- повысить безопасность и изоляцию.

---

# `lsblk`

`lsblk` показывает блочные устройства, разделы и точки монтирования.

Команда:

```
lsblk
```

Пример:

```
NAME        SIZE TYPE MOUNTPOINT
sda          50G disk
├─sda1        1G part /boot
└─sda2       49G part /
```

Полезный вариант:

```
lsblk -f
```

Показывает файловые системы и UUID:

```
NAME   FSTYPE UUID                                 MOUNTPOINT
sda1   ext4   a1b2-c3d4                            /boot
sda2   ext4   e5f6-g7h8                            /
```

Ещё полезно:

```
lsblk -o NAME,SIZE,FSTYPE,TYPE,MOUNTPOINT,UUID
```

---

# `blkid`

`blkid` показывает информацию о файловых системах, UUID и типах разделов.

Команда:

```
sudo blkid
```

Пример:

```
/dev/sda1: UUID="a1b2-c3d4" TYPE="ext4"
/dev/sda2: UUID="e5f6-g7h8" TYPE="xfs"
```

Обычно `blkid` используют, когда настраивают `/etc/fstab`.

Лучше монтировать диски по UUID, а не по имени `/dev/sdb1`, потому что имя диска может измениться после перезагрузки.

---

# `fdisk`

`fdisk` — утилита для просмотра и изменения таблицы разделов.

Посмотреть разделы:

```
sudo fdisk -l
```

Открыть диск для редактирования:

```
sudo fdisk /dev/sdb
```

Внутри `fdisk` часто используются команды:

```
p   print partition table
n   new partition
d   delete partition
w   write changes
q   quit without saving
```

Важно: `fdisk` работает с разделами, а не с файлами.

Ошибки в `fdisk` могут привести к потере данных.

---

# `parted`

`parted` — ещё одна утилита для работы с разделами.

Часто используется для GPT-разметки и больших дисков.

Посмотреть разметку:

```
sudo parted  /dev/sdb print
```

Создать GPT-таблицу:

```
sudo parted /dev/sdb mklabel gpt
```

Создать раздел:

```
sudo parted /dev/sdb mkpart primary ext4 0% 100%
```

`fdisk` чаще встречается в простых задачах, `parted` — в более современных и автоматизированных сценариях.

---

# Filesystems

**Filesystem** — это способ организации файлов на разделе или volume.

Файловая система определяет:

- как хранятся файлы;
- как хранятся директории;
- как работают права;
- как работают inode;
- как восстанавливаются данные после сбоя;
- какие есть лимиты;
- можно ли делать snapshot;
- можно ли сжимать данные.

Примеры файловых систем:

```
ext4
xfs
btrfs
vfat
ntfs
tmpfs
```

Создать файловую систему:

```
sudo mkfs.ext4 /dev/sdb1
```

Или:

```
sudo mkfs.xfs /dev/sdb1
```

Важно: `mkfs` стирает старые данные на разделе.

---

# ext4

`ext4` — одна из самых популярных файловых систем в Linux.

Плюсы:

- стабильная;
- простая;
- хорошо подходит для большинства серверов;
- поддерживает journaling;
- можно уменьшать и увеличивать файловую систему.

Создать ext4:

```
sudo mkfs.ext4 /dev/sdb1
```

Проверить ext4:

```
sudo fsck.ext4 /dev/sdb1
```

Расширить ext4:

```
sudo resize2fs /dev/sdb1
```

Особенность: ext4 заранее создаёт inode. Поэтому на ext4 может закончиться количество inode, даже если место ещё есть.

---

# xfs

`xfs` — современная и производительная файловая система.

Часто используется в RHEL/CentOS/Rocky/AlmaLinux.

Плюсы:

- хорошо работает с большими файлами;
- хорошо масштабируется;
- быстро работает на больших volume;
- используется по умолчанию во многих enterprise-дистрибутивах.

Создать xfs:

```
sudo mkfs.xfs /dev/sdb1
```

Расширить xfs:

```
sudo xfs_growfs /mount/point
```

Например:

```
sudo xfs_growfs /
```

Важный момент:

```
xfs можно увеличить, но нельзя нормально уменьшить стандартными средствами.
```

То есть shrink для xfs — проблема.

---

# btrfs

`btrfs` — современная copy-on-write файловая система.

Поддерживает:

- snapshots;
- subvolumes;
- compression;
- checksums;
- online resize;
- встроенные возможности, похожие на volume management.

Пример создания:

```
sudo mkfs.btrfs /dev/sdb1
```

Плюсы:

- snapshot'ы;
- удобно для rollback;
- сжатие;
- контроль целостности данных.

Минусы:

- сложнее в эксплуатации;
- не везде используется как стандарт;
- требует понимания особенностей.

Часто btrfs встречается в openSUSE, Fedora и некоторых desktop/server setups.

---

# Mount

**Mount** — это подключение файловой системы к директории.

В Linux нет отдельных дисков `C:`, `D:` как в Windows.

Вместо этого есть единое дерево:

```
/
├── boot
├── home
├── var
└── mnt
```

Чтобы использовать файловую систему, её нужно примонтировать в директорию.

Пример:

```
sudo mount /dev/sdb1 /mnt/data
```

После этого содержимое `/dev/sdb1` будет доступно через:

```
/mnt/data
```

---

# Unmount

**Unmount** — это отключение файловой системы от точки монтирования.

Команда:

```
sudo umount /mnt/data
```

Или:

```
sudo umount /dev/sdb1
```

Если файловая система занята, будет ошибка:

```
target is busy
```

Это значит, что кто-то использует файлы внутри этой директории.

Найти процесс:

```
sudo lsof +D /mnt/data
```

Или:

```
sudo fuser -vm /mnt/data
```

---

# `/etc/fstab`

`/etc/fstab` — файл, который описывает, какие файловые системы нужно монтировать автоматически при загрузке системы.

Пример:

```
UUID=e5f6-g7h8 /data ext4 defaults 0 2
```

Формат:

```
<device> <mountpoint> <filesystem> <options> <dump> <fsck>
```

Пример:

```
UUID=1111-2222 /data ext4 defaults,nofail 0 2
```

Где:

```
UUID=1111-2222   что монтировать
/data            куда монтировать
ext4             тип файловой системы
defaults,nofail  опции
0                dump
2                порядок fsck
```

Проверить `/etc/fstab` без перезагрузки:

```
sudo mount -a
```

Это очень важная команда.

Если в `/etc/fstab` ошибка, сервер может не загрузиться нормально.

Для облачных или дополнительных дисков часто добавляют `nofail`, чтобы сервер загрузился даже если диск недоступен.

---

# `mount`

Команда `mount` показывает текущие монтирования и позволяет монтировать файловые системы.

Показать все mounts:

```
mount
```

Более удобно:

```
findmnt
```

Примонтировать вручную:

```
sudo mount /dev/sdb1 /data
```

Примонтировать всё из `/etc/fstab`:

```
sudo mount -a
```

---

# `umount`

`umount` размонтирует файловую систему.

```
sudo umount /data
```

Если занято:

```
sudo lsof +D /data
```

Или:

```
sudo fuser -vm /data
```

Иногда можно сделать lazy unmount:

```
sudo umount -l /data
```

Но это нужно использовать осторожно.

---

# `df -h`

`df` показывает свободное и занятое место на файловых системах.

Команда:

```
df -h
```

Пример:

```
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda2        50G   45G  5G   90% /
/dev/sdb1       100G   20G  80G  20% /data
```

Расшифровка:

```
Size   общий размер
Used   использовано
Avail  доступно
Use%   процент использования
Mounted on  куда примонтировано
```

Для SRE это одна из первых команд при проблемах с диском.

---

# `du -sh`

`du` показывает, сколько места занимает файл или директория.

Команда:

```
du -sh /var/log
```

Пример:

```
2.4G /var/log
```

Посмотреть размер директорий внутри `/var`:

```
sudo du -h --max-depth=1 /var
```

Отсортировать:

```
sudo du -h --max-depth=1 /var | sort -h
```

Найти самые тяжёлые директории:

```
sudo du -xhd1 / | sort -h
```

Ключ `-x` означает не переходить на другие файловые системы.

Это полезно, если у тебя `/`, `/home`, `/var` находятся на разных mount point.

# Inodes

**Inode** — это структура данных, которая хранит метаданные файла.

Inode хранит:

- владельца;
- группу;
- права;
- timestamps;
- размер;
- ссылки на блоки данных;
- количество hard links.

Имя файла хранится не в inode, а в директории.

Упрощённо:

```
filename → inode → data blocks
```

У файла есть inode number.

Посмотреть inode:

```
ls -li
```

Пример:

```
1234567 -rw-r--r-- 1 user user 100 file.txt
```

`1234567` — номер inode.

---

# `df -i`

`df -i` показывает использование inode.

Команда:

```
df -i
```

Пример:

```
Filesystem      Inodes  IUsed   IFree IUse% Mounted on
/dev/sda2      3276800 3200000  76800   98% /
```

Если inode закончились, новые файлы создать нельзя, даже если место на диске ещё есть.

Типичная ошибка:

```
No space left on device
```

Но при этом `df -h` может показывать свободное место.

Тогда надо проверить:

```
df -i
```

# Что делать, если закончилось место

Сначала проверить:

```
df -h
```

Понять, какая файловая система заполнена:

```
Mounted on
/
 /var
 /home
 /data
```

Потом искать, что занимает место.

Проверить крупные директории:

```
sudo du -xhd1 / | sort -h
```

Если заполнен `/var`:

```
sudo du -xhd1 /var | sort -h
```

Частые причины:

- большие логи;
- Docker images/containers/volumes;
- старые архивы;
- дампы баз данных;
- core dumps;
- временные файлы;
- кэш пакетного менеджера;
- journalctl logs;
- файл удалён, но всё ещё открыт процессом.

---

## Проверить логи systemd

```
journalctl --disk-usage
```

Очистить старые логи:

```
sudo journalctl --vacuum-time=7d
```

Или ограничить размер:

```
sudo journalctl --vacuum-size=1G
```

---

## Проверить `/var/log`

```
sudo du -sh /var/log/*
```

Большие `.log` файлы можно очистить так:

```
sudo truncate -s 0 /var/log/some.log
```

Лучше не делать:

```
rm /var/log/some.log
```

Если файл открыт процессом, место может не освободиться до рестарта процесса.

---

## Удалённый файл всё ещё занимает место

Такое бывает, когда файл удалили, но процесс держит его открытым.

Проверить:

```
sudo lsof | grep deleted
```

Пример:

```
nginx  1234  /var/log/nginx/access.log (deleted)
```

Решение:

```
sudo systemctl restart nginx
```

Или аккуратно перезапустить процесс, который держит файл.

# Что делать, если закончились inodes

Проверить:

```
df -i
```

Найти директории с большим количеством файлов:

```
sudo find / -xdev -type f | cut -d / -f 2 | sort | uniq -c | sort -n
```

Более практично искать внутри подозрительных директорий:

```
sudo find /var -xdev -type f | wc -l
```

Посчитать файлы по директориям:

```
sudo find /var -xdev -type f | sed 's|/[^/]*$||' | sort | uniq -c | sort -n
```

Частые причины окончания inode:

- миллионы маленьких файлов;
- cache;
- session files;
- временные файлы;
- mail queue;
- Docker overlay;
- npm/yarn/pip cache;
- логи, которые ротируются слишком часто;
- директории приложений с мелкими объектами.

Пример чистки временных файлов:

```
sudo find /tmp -type f -mtime +7 -delete
```

Но удалять нужно осторожно.

Сначала лучше посмотреть:

```
sudo find /tmp -type f -mtime +7
```

# LVM

**LVM** — Logical Volume Manager.

Он добавляет слой абстракции между физическими дисками и файловыми системами.

Обычная схема:

```
Disk → Partition → Filesystem → Mount
```

С LVM:

```
Disk → Physical Volume → Volume Group → Logical Volume → Filesystem → Mount
```

Зачем нужен LVM:

- удобно расширять диски;
- можно объединять несколько дисков в одну группу;
- можно создавать logical volumes нужного размера;
- можно делать snapshot'ы;
- проще управлять storage на серверах.

---

# Physical Volume

**Physical Volume**, или PV, — это физический диск или раздел, который отдан под LVM.

Пример:

```
/dev/sdb
/dev/sdb1
/dev/nvme0n1p3
```

Создать PV:

```
sudo pvcreate /dev/sdb
```

Посмотреть PV:

```
sudo pvs
```

Или подробнее:

```
sudo pvdisplay
```

---

# Volume Group

**Volume Group**, или VG, — это группа физических volume.

Пример:

```
/dev/sdb + /dev/sdc → vg_data
```

Создать VG:

```
sudo vgcreate vg_data /dev/sdb
```

Посмотреть VG:

```
sudo vgs
```

Подробнее:

```
sudo vgdisplay
```

Добавить новый диск в VG:

```
sudo vgextend vg_data /dev/sdc
```

---

# Logical Volume

**Logical Volume**, или LV, — это логический диск внутри Volume Group.

Именно на LV обычно создают файловую систему.

Создать LV размером 20G:

```
sudo lvcreate -L 20G -n lv_data vg_data
```

После этого появится устройство:

```
/dev/vg_data/lv_data
```

Создать файловую систему:

```
sudo mkfs.ext4 /dev/vg_data/lv_data
```

Создать mount point:

```
sudo mkdir /data
```

Примонтировать:

```
sudo mount /dev/vg_data/lv_data /data
```

Посмотреть LV:

```
sudo lvs
```

Подробнее:

```
sudo lvdisplay
```

---

# Resize filesystem

Resize обычно состоит из двух частей:

```
1. Увеличить block device / LV
2. Увеличить filesystem
```

Если используется LVM, сначала расширяют LV.

Пример для LVM:

```
sudo lvextend -L +10G /dev/vg_data/lv_data
```

Или занять всё свободное место в VG:

```
sudo lvextend -l +100%FREE /dev/vg_data/lv_data
```

Потом расширить файловую систему.

Для ext4:

```
sudo resize2fs /dev/vg_data/lv_data
```

Для xfs:

```
sudo xfs_growfs /data
```

Можно сразу расширить LV и filesystem:

```
sudo lvextend -r -L +10G /dev/vg_data/lv_data
```

Ключ `-r` пытается автоматически расширить файловую систему.

---

## Увеличение ext4

```
sudo lvextend -L +10G /dev/vg_data/lv_data
sudo resize2fs /dev/vg_data/lv_data
```

---

## Увеличение xfs

```
sudo lvextend -L +10G /dev/vg_data/lv_data
sudo xfs_growfs /data
```

Важно: для `xfs_growfs` указывается mount point, а не block device.

Правильно:

```
sudo xfs_growfs /data
```

Не так:

```
sudo xfs_growfs /dev/vg_data/lv_data
```

# Swap

**Swap** — это область на диске, которую Linux может использовать как дополнительную память, когда не хватает RAM.

Swap бывает:

- swap partition;
- swap file.

Проверить swap:

```
swapon --show
```

Или:

```
free -h
```

Пример:

```
              total        used        free
Mem:           2.0G        1.5G        200M
Swap:          2.0G        300M        1.7G
```

Swap не заменяет RAM.

Если сервер активно использует swap, это часто признак нехватки памяти.

---

# Создать swap file

Создать файл:

```
sudo fallocate -l 2G /swapfile
```

Выставить права:

```
sudo chmod 600 /swapfile
```

Сделать swap:

```
sudo mkswap /swapfile
```

Включить:

```
sudo swapon /swapfile
```

Проверить:

```
swapon --show
```

Добавить в `/etc/fstab`:

```
/swapfile none swap sw 0 0
```

---

# `swapon`

`swapon` включает swap.

Показать активный swap:

```
swapon --show
```

Включить swap file:

```
sudo swapon /swapfile
```

Включить всё из `/etc/fstab`:

```
sudo swapon -a
```

---

# `swapoff`

`swapoff` отключает swap.

Отключить конкретный swap:

```
sudo swapoff /swapfile
```

Отключить весь swap:

```
sudo swapoff -a
```

Важно: если в RAM нет места для данных из swap, `swapoff` может зависнуть или привести к проблемам.

Перед отключением проверь:

```
free -h
```

# Практический сценарий: добавить новый диск

Допустим, появился диск `/dev/sdb`.

Проверить:

```
lsblk
```

Создать раздел:

```
sudo fdisk /dev/sdb
```

Создать файловую систему:

```
sudo mkfs.ext4 /dev/sdb1
```

Создать mount point:

```
sudo mkdir /data
```

Примонтировать:

```
sudo mount /dev/sdb1 /data
```

Проверить:

```
df -h
```

Узнать UUID:

```
sudo blkid /dev/sdb1
```

Добавить в `/etc/fstab`:

```
UUID=<uuid> /data ext4 defaults,nofail 0 2
```

Проверить:

```
sudo mount -a
```

# Практический сценарий: закончилось место на `/`

Проверить:

```
df -h
```

Найти крупные директории:

```
sudo du -xhd1 / | sort -h
```

Если много в `/var`:

```
sudo du -xhd1 /var | sort -h
```

Проверить journal:

```
journalctl --disk-usage
```

Почистить journal:

```
sudo journalctl --vacuum-time=7d
```

Проверить Docker:

```
docker system df
```

Проверить удалённые, но открытые файлы:

```
sudo lsof | grep deleted
```

# Практический сценарий: место есть, но файлы не создаются

Ошибка:

```
No space left on device
```

Проверяешь место:

```
df -h
```

Место есть.

Тогда проверяешь inode:

```
df -i
```

Если `IUse%` близко к 100%, закончились inode.

Нужно искать директорию с огромным количеством мелких файлов.

# Что важно знать на собеседовании

Минимум нужно уверенно объяснять:

```
/dev/sda        диск
/dev/sda1       раздел
filesystem     ext4/xfs/btrfs
mount point     директория, куда подключена ФС
/etc/fstab      автомонтирование при загрузке
df -h           место по файловым системам
du -sh          размер файлов/директорий
df -i           inode usage
LVM             гибкое управление дисками
swap            дисковая область как запас для RAM
```

Очень частый вопрос:

```
df -h показывает свободное место, но файл создать нельзя. Почему?
```

Ответ:

```
Скорее всего, закончились inode. Проверить через df -i.
```

Ещё частый вопрос:

```
Файл удалили, но место не освободилось. Почему?
```

Ответ:

```
Файл может быть всё ещё открыт процессом. Проверить через lsof | grep deleted.
```

# Главное понимание

Диск сам по себе не равен директории.

Чтобы диск стал доступен в Linux, обычно нужно:

```
1. Увидеть block device
2. Создать partition
3. Создать filesystem
4. Создать mount point
5. Примонтировать filesystem
6. Добавить запись в /etc/fstab
```

Пример итоговой цепочки:

```
/dev/sdb
  → /dev/sdb1
    → ext4
      → /data
```
