## Главное различие

**Архив** — это упаковка нескольких файлов/директорий в один файл.

**Сжатие** — это уменьшение размера файла.

Например:

```
tar -cf backup.tar /var/log
```

Это **архив**, но без сжатия.

```
tar -czf backup.tar.gz /var/log
```

Это **архив + gzip-сжатие**.

---

# `tar`

`tar` — одна из главных утилит для архивирования в Linux.

Название исторически означает **tape archive**.

`tar` сам по себе обычно **собирает файлы в один архив**, а сжатие подключается отдельно через gzip/xz/bzip2.

---

## Основные ключи `tar`

```
tar -cf archive.tar file1 file2 dir/
```

Где:

```
-c
```

создать архив, от слова **create**.

```
-f
```

указать имя файла архива.

```
-v
```

показывать процесс, от слова **verbose**.

```
-x
```

распаковать архив, от слова **extract**.

```
-t
```

показать содержимое архива, от слова **list/table**.

```
-z
```

использовать `gzip`.

```
-J
```

использовать `xz`.

```
-j
```

использовать `bzip2`.

---

# Как создать архив

## Обычный `.tar` без сжатия

```
tar -cf archive.tar file1.txt file2.txt
```

Архив создастся, но размер сильно не уменьшится.

---

## Архивировать директорию

```
tar -cf project.tar project/
```

Это создаст архив директории `project`.

---

## Создать `.tar.gz`

```
tar -czf project.tar.gz project/
```

Расшифровка:

```
-c
```

создать архив.

```
-z
```

сжать через gzip.

```
-f
```

указать файл архива.

---

## Создать `.tar.xz`

```
tar -cJf project.tar.xz project/
```

`xz` обычно сжимает лучше, чем gzip, но медленнее.

---

## Создать `.tar.bz2`

```
tar -cjf project.tar.bz2 project/
```

`bzip2` тоже сжимает лучше gzip, но часто медленнее.

---

# Как распаковать архив

## Распаковать `.tar`

```
tar -xf archive.tar
```

---

## Распаковать `.tar.gz`

```
tar -xzf archive.tar.gz
```

---

## Распаковать `.tar.xz`

```
tar -xJf archive.tar.xz
```

---

## Распаковать `.tar.bz2`

```
tar -xjf archive.tar.bz2
```

---

## Распаковать в конкретную директорию

```
tar -xzf archive.tar.gz -C /tmp/
```

Ключ:

```
-C
```

означает “распаковать в указанную директорию”.

Важно: директория должна существовать.

```
mkdir -p /tmp/mybackuptar -xzf archive.tar.gz -C /tmp/mybackup
```

## Посмотреть содержимое `.tar.gz`

# Полезные примеры `tar`

## Архивировать `/var/log`

```
sudo tar -czf logs.tar.gz /var/log
```

Но при этом внутри архива путь может быть:

```
var/log/...
```

Обычно `tar` убирает начальный `/`, чтобы при распаковке случайно не перезаписать системные файлы.

---

## Архивировать содержимое директории, а не саму директорию

Допустим, есть директория:

```
project/
```

Если сделать так:

```
tar -czf project.tar.gz project/
```

то внутри архива будет директория `project`.

А если нужно архивировать только содержимое:

```
tar -czf project.tar.gz -C project .
```

Это часто используется в деплое и CI/CD.

---

## Исключить файлы из архива

```
tar --exclude='node_modules' -czf app.tar.gz app/
```

Можно исключить несколько:

```
tar --exclude='node_modules' --exclude='.git' -czf app.tar.gz app/
```

---

## Сохранить права и владельцев

`tar` обычно сохраняет права файлов.

Но при распаковке владельцы корректно восстановятся только если распаковывать от root.

```
sudo tar -xpf backup.tar
```

Ключ:

```
-p
```

сохраняет permissions.

---

# `gzip`

`gzip` — утилита для сжатия файлов.

Она **сжимает один файл**, а не директорию.

```
gzip file.txt
```

После выполнения появится:

```
file.txt.gz
```

А оригинальный `file.txt` обычно исчезнет.

---

## Распаковать gzip

```
gunzip file.txt.gz
```

Или:

```
gzip -d file.txt.gz
```

---

## Сжать и оставить оригинал

```
gzip -k file.txt
```

Ключ:

```
-k
```

означает keep, оставить оригинальный файл.

---

## Посмотреть содержимое `.gz` без распаковки

```
zcat file.txt.gz
```

Или читать через `less`:

```
zless file.txt.gz
```

Искать через `grep`:

```
zgrep "error" app.log.gz
```

Это очень полезно при работе со старыми логами.

---

# `gunzip`

`gunzip` — команда для распаковки `.gz`.

```
gunzip file.gz
```

То же самое, что:

```
gzip -d file.gz
```

Пример:

```
gunzip access.log.gz
```

Получим:

```
access.log
```

# `zip`

`zip` часто используется в Windows/macOS-среде.

В отличие от `tar`, `zip` умеет и архивировать, и сжимать.

---
``
## Создать zip-архив

```
zip archive.zip file1.txt file2.txt
```

---

## Архивировать директорию через zip

```
zip -r project.zip project/
```

Ключ:

```
-r
```

означает recursive, то есть архивировать директорию рекурсивно.

---

## Исключить файлы из zip

```
zip -r project.zip project/ -x "project/node_modules/*"
```

# `unzip`

`unzip` используется для распаковки `.zip`.

```

```

---

## Распаковать zip в конкретную директорию

```
unzip archive.zip -d /tmp/project
```

## Посмотреть содержимое zip-архива

unzip -l archive.zip

# `xz`

`xz` — сильное сжатие, часто лучше gzip, но медленнее.

Используется, например, для больших архивов, образов, пакетов.

---

## Сжать файл через xz

```
xz file.txt
```

Получится:

```
file.txt.xz
```

---

## Распаковать `.xz`

```
unxz file.txt.xz
```

Или:

```
xz -d file.txt.xz
```

---

## Использование с tar

Создать:

```
tar -cJf archive.tar.xz directory/
```

Распаковать:

```
tar -xJf archive.tar.xz
```

---

# `bzip2`

`bzip2` — старый, но всё ещё встречающийся алгоритм сжатия.

Обычно сжимает лучше gzip, но медленнее.

---

## Сжать файл

```
bzip2 file.txt
```

Получится:

```
file.txt.bz2
```

---

## Распаковать

```
bunzip2 file.txt.bz2
```

Или:

```
bzip2 -d file.txt.bz2
```

---

## Использование с tar

Создать:

```
tar -cjf archive.tar.bz2 directory/
```

Распаковать:

```
tar -xjf archive.tar.bz2
```

---

# Сравнение gzip, xz, bzip2

Условно:

|Формат|Скорость|Сжатие|Частое использование|
|---|---|---|---|
|`gzip`|быстро|среднее|логи, backup, `.tar.gz`|
|`xz`|медленно|сильное|большие архивы, образы, пакеты|
|`bzip2`|средне/медленно|хорошее|старые архивы, legacy-системы|
|`zip`|удобно|среднее|обмен с Windows/macOS|

На практике в Linux чаще всего встречается:

```
.tar.gz
```

# Как передать архив по SSH

Есть несколько способов.

---

## 1. Через `scp`

Создать архив:

```
tar -czf project.tar.gz project/
```

Передать на сервер:

```
scp project.tar.gz user@server:/home/user/
```

Пример:

```
scp backup.tar.gz root@192.168.1.10:/root/
```

---

## 2. Через `rsync`

```
rsync -avz project.tar.gz user@server:/home/user/
```

Ключи:

```
-a
```

archive mode, сохраняет права, даты, симлинки.

```
-v
```

verbose.

```
-z
```

сжимать трафик при передаче.

`rsync` удобнее `scp`, если файл большой или передача может прерваться.

---

## 3. Архивировать и передать сразу по SSH без создания файла

Очень полезный способ:

```
tar -czf - project/ | ssh user@server "cat > project.tar.gz"
```

Что тут происходит:

```
tar -czf - project/
```

создаёт архив и пишет его в stdout, то есть в поток.

```
|
```

передаёт поток дальше.

```
ssh user@server "cat > project.tar.gz"
```

на удалённом сервере сохраняет поток в файл `project.tar.gz`.

---

## 4. Архивировать локально и сразу распаковать на сервере

```
tar -czf - project/ | ssh user@server "tar -xzf - -C /home/user/"
```

Это значит:

1. Локально создаём архив в поток.
2. Передаём поток по SSH.
3. На сервере сразу распаковываем.

Очень часто используется для быстрых переносов директорий.

---

## 5. Забрать директорию с сервера и распаковать локально

```
ssh user@server "tar -czf - /var/log/nginx" | tar -xzf - -C /tmp/
```

Сервер создаёт архив в поток, а локальная машина его сразу распаковывает.

---

# Частые ошибки

## Ошибка 1: забыли `-f`

Неправильно:

```
tar -cz archive.tar.gz dir/
```

Правильно:

```
tar -czf archive.tar.gz dir/
```

---

## Ошибка 2: перепутали `c` и `x`

Создание архива:

```
tar -czf archive.tar.gz dir/
```

Распаковка:

```
tar -xzf archive.tar.gz
```

`c` — create.

`x` — extract.

---

## Ошибка 3: распаковали архив не туда

Перед распаковкой лучше посмотреть содержимое:

```
tar -tzf archive.tar.gz
```

А потом распаковывать в нужную директорию:

```
tar -xzf archive.tar.gz -C /tmp/test
```

---

## Ошибка 4: попытка gzip-нуть директорию

Так не надо:

```
gzip project/
```

`gzip` сжимает файл, а не директорию.

Правильно:

```
tar -czf project.tar.gz project/
```

---

# Что важно для SRE/DevOps

Для SRE важно уметь:

1. Быстро собрать backup:

```
tar -czf backup.tar.gz /path
```

2. Проверить содержимое архива:

```
tar -tzf backup.tar.gz
```

3. Распаковать в нужное место:

```
tar -xzf backup.tar.gz -C /path
```

4. Передать архив на сервер:

```
scp backup.tar.gz user@server:/path
```

5. Передать директорию по SSH без временного файла:

```
tar -czf - dir/ | ssh user@server "tar -xzf - -C /target"
```

# Что могут спросить на собеседовании

## Чем отличается `tar` от `gzip`?

`tar` объединяет много файлов в один архив.

`gzip` сжимает один файл.

Поэтому часто используют вместе:

```
tar + gzip = .tar.gz
```

---

## Что такое `.tar.gz`?

Это tar-архив, сжатый gzip.

---

## Как посмотреть содержимое архива без распаковки?

```
tar -tzf archive.tar.gz
```

---

## Как распаковать архив в конкретную директорию?

```
tar -xzf archive.tar.gz -C /target
```

---

## Как передать директорию на сервер без создания архива на диске?

```
tar -czf - dir/ | ssh user@server "tar -xzf - -C /target"
```

---

## Почему архив может распаковаться в неожиданную директорию?

Потому что внутри архива уже сохранены пути файлов.

Перед распаковкой лучше проверить:

```
tar -tzf archive.tar.gz
```

---

## Что лучше использовать: `scp` или `rsync`?

Для простой передачи можно `scp`.

Для больших файлов, повторной синхронизации и нестабильной сети лучше `rsync`.

```
rsync -avz archive.tar.gz user@server:/path/
```
